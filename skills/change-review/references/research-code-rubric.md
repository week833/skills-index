# 研究程式檢核表

審查者逐項檢查這次變更，八項都要留下結論：有發現／未發現問題／不適用／未能確認。

- 專案特有的規則（固定路徑、資料來源、驗收方式、不可破壞的契約）以專案的 `AGENTS.md` 與它指向的文件為準。本表不重述那些內容；兩者不一致時依專案規則，並在報告指出。
- 每一項分成「要看什麼」與「要引用的證據」。只憑檔名、註解或 commit 訊息下的結論不算證據。
- 標示「已查證」的行為，是在文末〈查證環境〉所列的版本上實際執行確認的；版本不同時請以實際環境為準。

## 1 需求與範圍

要看什麼：

- 變更是否做到使用者要求的事，有沒有少做。
- 需求本身是否與專案規則或本表其他項目衝突，例如要求的特徵必然用到未來資料。有的話要指出，不要因為「照需求做了」就放行。
- 有沒有多做：需求以外的重構、改名、格式整理，或順手改掉的其他問題。
- 現有的程式、測試或設定是否被搬移、改名或刪除。在 status 輸出中是 `D`、`R`，或「一行 ` D` 加一行 `??`」的組合（未暫存的改名會這樣顯示，已查證）。
- 是否新增日期化副本或備份副本，例如檔名帶日期、`_old`、`_bak`、`_backup`、`_copy`。
- 是否動到使用者授權範圍以外的目錄，或其他專案的檔案。

要引用的證據：

- 需求原文中對應的句子，加上實作它的檔案與行號；多做或少做的部分各自舉出行號。
- status 輸出中刪除、改名與新增的那幾行原文。

## 2 時間點正確性與前視

先找出「預測時點」（例如當日收盤後、次日開盤前）在程式的哪裡決定，再看下列各點。

要看什麼：

- 特徵與標籤的對齊：特徵用到的每個值，在預測時點是否已經可得；標籤是否只用預測時點之後的值；有沒有欄位同時出現在特徵與標籤的計算裡。
- 位移方向（已查證）：`shift(1)` 把前一列的值放到本列，是過去值；`shift(-1)` 把後一列的值放到本列，是未來值，只能用來做標籤。`pct_change(-1)` 與 `diff(-1)` 同樣取後一列。
- 長表（多檔股票上下相接）：直接對欄位做 `shift(1)`，每檔股票的第一列會拿到上一檔股票的最後一筆；`rolling`、`pct_change`、`diff` 與 `ffill` 同樣會跨到上一檔股票（以上已查證）。這些都要先依股票代號 `groupby`，而且每檔股票的列要依日期排序。`merge_asof` 沒有用 `by=` 指定股票代號時，可能合併到別檔股票的列（已查證）。
- 滾動視窗（已查證）：`rolling(n)` 的視窗結束在本列，而且包含本列；`rolling(n, center=True)` 會用到後面的列。本列的值在預測時點還不可得時，要先 `shift(1)` 再滾動。
- 補值與轉換（已查證）：`ffill` 用較早的值；`bfill` 與 `interpolate()` 會用到較晚的值。用整段期間算出的平均、分位數、排名或標準化參數來補值或轉換，等於用了未來資料。
- as-of 合併：合併鍵必須是資料的可得時間（公告、發布或入庫時間），不是資料所屬的期間（財報季別、營收月份、交易日）。可得時間不明時應視為未知，不能拿資料日期代替。`pd.merge_asof` 預設 `direction="backward"`、`allow_exact_matches=True`：取鍵值不晚於左表的最後一筆，鍵值相等也算；`direction="forward"` 與 `"nearest"` 可能取到較晚的列（以上已查證）。鍵值相等的那一筆，在預測時點是否真的已經可得？
- 切分：訓練、驗證、測試是否依時間先後切開。`train_test_split` 預設 `shuffle=True`，會打散時間順序；`KFold` 預設不打散，但第一折是拿較晚的列訓練、較早的列測試；`TimeSeriesSplit` 依列的位置切，`gap` 預設 0 而且以列數計算，一天有多檔股票的資料直接丟進去時，同一天的列可能同時落在訓練與測試兩邊，改對不重複的日期切分就不會（以上已查證）。
- 重疊的標籤視窗：標籤涵蓋未來 h 個交易日時，訓練期最後幾天的標籤會用到測試期的價格。訓練與測試之間是否留了足夠的間隔（gap／purge）？
- 前處理只用訓練資料配適：`StandardScaler`、`SimpleImputer`、特徵篩選、分箱或目標編碼，是否在切分之前就對全部資料 `fit` 或 `fit_transform`；交叉驗證時是否每一折各自配適（例如包進 `Pipeline`）。超參數、門檻或特徵的挑選是否看過測試期的結果。
- 提前停止（已查證）：`HistGradientBoostingClassifier` 與 `HistGradientBoostingRegressor` 預設 `early_stopping="auto"`，訓練資料多於 10,000 列時啟用（10,000 列未啟用、10,001 列啟用），並從訓練資料隨機留出 `validation_fraction=0.1` 當驗證集，不是取時間上最後的一段。變更若依賴這個預設值，要指出來。
- 修訂過的資料：價格、財報或總體經濟數列是否為預測時點當時可得的版本。還原股價、重編財報與事後修正的數值可能在事後被改寫；是否以截止日之前凍結的快照為準，或留有可以重建的紀錄。
- 股票池：每個日期的股票池是否為當日的成分（包含當時上市、後來下市的股票），而不是拿現在的清單回推歷史。

要引用的證據：

- 特徵與標籤各自的檔案、行號與原文，並指出預測時點在哪一行決定。
- 合併、切分、配適各自的行號；h 與間隔的值在哪裡設定。
- 讀取資料的行號，以及截止日、快照或版本紀錄在哪裡；找不到就寫「未見紀錄」。

## 3 可重現性

要看什麼：

- 隨機來源是否都有固定的種子：模型的 `random_state`、`np.random.default_rng(seed)`、抽樣與打散。`HistGradientBoosting*` 沒有固定 `random_state` 時，同一份資料連續訓練兩次，下列情形的預測不同：啟用提前停止（10,001 列）；`early_stopping=False` 但訓練資料多於 200,000 列（分箱的門檻取自隨機抽樣的 200,000 列；試過 200,001 列與 250,000 列）；`early_stopping=False` 但 `max_features` 小於 1（10,001 列、`max_features=0.5`）。這些情形固定 `random_state` 之後，兩次結果相同（以上已查證）。所以 `early_stopping=False` 不能代替固定種子。
- 順序是否確定：排序鍵有並列值時，是否加了次要鍵或使用穩定排序。`DataFrame.sort_values` 預設 `kind="quicksort"`；它的說明文件寫明只有 `mergesort` 與 `stable` 是穩定排序，而且 `kind` 只在依單一欄位排序時適用（已查證）。
- 是否未經排序就依賴 `set` 的走訪順序、目錄列舉（`os.listdir`、`glob`、`Path.iterdir`）的順序，或沒有 `ORDER BY` 的 SQL 查詢結果的順序。字串組成的 `set` 在不同次執行之間順序可能不同（已查證：12 次執行出現不只一種順序）。
- 是否記錄了資料截止日、資料快照或來源版本、套件版本與參數，足以重跑出相同結果。
- 計算是否依賴當下時間（`datetime.now()`、`date.today()`、`time.time()`、`pd.Timestamp.now()`）或網路回應；「今天」應該由參數或資料截止日決定。

要引用的證據：

- 每個隨機來源與排序的行號；種子與截止日從哪裡傳入。
- 用到當下時間或網路的行號，以及它是否影響計算結果（只寫進日誌時間戳記的不算）。

## 4 機密

要看什麼：

- 變更中是否出現 token、金鑰、密碼、cookie，或帶有它們的 URL：程式碼、設定、測試資料、文件、範例與 commit 訊息都要看。測試資料只能用一眼就看得出是假的值。
- 含 token 的 URL（token 在路徑或查詢參數裡）是否被寫進日誌、例外訊息、報告、輸出檔，或回傳給呼叫端；是否記錄了帶有完整 URL 的物件屬性，例如 `urllib` 的 `HTTPError.url` 與 `Request.full_url`（這兩個屬性含完整 URL，已查證）。
- 是否列印或記錄環境變數、整份設定或整個請求，例如 `print(os.environ)`，或把設定字典整包寫進日誌。
- `.ENV` 與其他機密檔是否仍被忽略、而且沒有被追蹤；`.gitignore` 裡的機密規則是否被移除或放寬，例如新增以 `!` 開頭、把機密檔重新納入的規則；變更清單裡是否出現 `.ENV`、`*.token`、`*.key` 之類的檔案。

要引用的證據：

- 檔案、行號與原文；機密的值以 `***` 遮蔽，只留變數名稱與前後文。
- 下列兩道指令的輸出（路徑換成專案實際的機密檔）。兩道都在 repository 根目錄執行，因為它們以目前所在的目錄解讀路徑（已查證）。第一道印出路徑表示被忽略；沒有輸出表示沒有被忽略，可能是沒有規則符合、被以 `!` 開頭的規則重新納入，或檔案已被追蹤（已查證）。第二道沒有輸出表示沒有被追蹤（已查證）。兩道都不會讀出檔案內容；不要開啟機密檔。
- 想知道是哪一條規則時，可以在第一道加上 `-v`。加了 `-v` 之後，以 `!` 開頭的規則也會印出來（例如 `.gitignore:9:!config/.ENV`），而且退出碼仍是 0，但那表示該路徑沒有被忽略；是否被忽略一律以不加 `-v` 的結果為準（已查證）。

```text
git --no-optional-locks --no-pager -c core.quotepath=off -c diff.autoRefreshIndex=false check-ignore .ENV
git --no-optional-locks --no-pager -c core.quotepath=off -c diff.autoRefreshIndex=false ls-files .ENV
```

## 5 輸出與路徑

要看什麼：

- 輸出、快取、報告、日誌、資料檔或模型檔是否出現在變更清單裡。未追蹤但沒被忽略的也算，因為 `git add -A` 會把它們一起加進去（已查證）。
- 固定路徑是否遵守專案自己的固定路徑清單與路徑登錄設定（位置見專案的 `AGENTS.md`）；有沒有新寫死的絕對路徑，或寫入其他專案、正式資料目錄的程式。
- 是否覆寫了專案規定只能追加或不得覆寫的檔案。
- 文字檔讀寫是否明確指定編碼。沒有啟用 Python 的 UTF-8 模式時，`open()`、`Path.read_text()`、`Path.write_text()` 沒有指定 `encoding` 就使用地區設定的預設編碼；`subprocess` 以 `text=True` 讀取輸出而沒有指定 `encoding` 時也一樣（已查證：在 ASCII 地區設定下，讀寫中文都失敗）。`pd.read_csv` 與 `DataFrame.to_csv` 傳入路徑而沒有指定 `encoding` 時，在同樣的地區設定下仍以 UTF-8 處理（已查證）。
- 輸出中文到主控台之前，是否把 stdout 與 stderr 設為 UTF-8，例如 `sys.stdout.reconfigure(encoding="utf-8")`。
- 路徑是否用 `pathlib` 組合，而不是手動串接分隔符號。

要引用的證據：

- status 輸出中相關檔案的那幾行，以及第 4 項 `check-ignore` 指令對該路徑的輸出。
- 每個讀寫點的檔案、行號與原文。

## 6 文件

要看什麼：

- 文件的每一處修改是否只記錄查證過的事實，而且找得到對應的程式、測試或執行紀錄。
- 是否寫進了計畫、待辦、預告，或其他還沒發生的事。
- 是否想用改文件的方式改變程式行為或驗收標準：只改了說明、門檻或規則的文字，程式與測試卻沒有變。
- 文件與程式不一致時，是否依實際的程式、測試與執行紀錄修正文件，而不是反過來。
- 規則檔（例如 `AGENTS.md`）或驗收標準本身被修改時，不論內容一律列出（至少列為「提醒」），由使用者確認是不是他的本意。

要引用的證據：

- 文件修改處的原文，加上佐證它的程式或測試的檔案與行號；找不到就寫「無對應證據」。

## 7 驗證證據

要看什麼：

- 「已測試」、「已修正」、「通過」這類說法，是否附上實際的指令與輸出，包含通過、失敗與略過的數量。只有退出碼 0，或只說檔案存在，都不算。在 pytest 9.2.0 上已查證：唯一的測試被略過時退出碼仍是 0；沒有任何斷言的測試會通過；沒有選到任何測試時退出碼是 5。
- 被改動的邏輯是否有測試，而且測試真的會失敗：斷言是否針對被改的行為；預期值是否獨立於受測程式算出，而不是用同一個函式算；是否把受測對象本身換成了假物件；是否新增 `skip` 或 `xfail`；是否放寬或刪除了原有的斷言。
- 前視與可重現性是否有對應的測試，例如：改動截止日之後的資料，截止日之前的特徵不變；相同種子重跑，結果相同。
- 審查者沒有獲准執行測試時，以上只能靠閱讀判斷，並在報告註明「未執行」。

要引用的證據：

- 作者聲稱的指令與輸出原文；沒有就寫「未提供」。
- 測試所在的檔案與行號；獲准執行時，附上實際指令與輸出節錄。

## 8 誠實陳述

要看什麼：

- 程式輸出、報告範本、文件或註解裡，是否新增「模型有效」、「準確率提升」、「策略可獲利」之類的說法，卻沒有可以查核的證據（資料期間、樣本外結果、產生結果的指令）。
- 是否移除或弱化了原有的揭露，例如「模型效果與交易效益未驗證」。
- 是否產生買進、賣出或持有的評等、目標價、部位大小或下單指示；是否呼叫券商或交易 API。
- 報酬、命中率、樣本數等數字，是否與產生它們的程式和資料期間一致；有沒有只挑有利的期間或指標。

要引用的證據：

- 該說法的檔案、行號與原文，以及佐證它的結果檔或指令；沒有就寫「無證據」。

## 查證環境

標示「已查證」的行為於 2026-11-13 在 Linux 上實際執行確認：Python 3.12.3、pandas 2.3.3、numpy 2.5.1、scikit-learn 1.9.1（相依的 scipy 1.18.1）、pytest 9.2.0、git 2.43.0。沒有在 Windows 上執行過。
