# NOTICE

## 這是什麼

`handoff-reader-test` 是 week833 的原創 agent skill：主代理先依查證過的來源寫好題目與參考答案，再請一位沒有任何背景的讀者只憑交接文件作答，藉此找出文件的缺漏、含糊、矛盾與過期內容。整份 skill 只有 Markdown、YAML 與授權文字檔，沒有腳本、hook、安裝程式或任何連網元件。

整理日期：2026-11-13。

## 構想來源

- 「讓沒有任何背景的讀者只憑文件回答問題，藉此檢驗文件」這個構想，來自 [anthropics/skills](https://github.com/anthropics/skills) 儲存庫中 `skills/doc-coauthoring` 這個 skill 的讀者測試階段。本工作流審查時，該儲存庫的版本是 commit `2c5958ecac7cee2b583967a2c4981d0f4a75c579`。依審查階段的比對，同一階段裡「沒有子代理時由使用者另開新對話」與「請讀者指出含糊與矛盾」兩個做法，本 skill 也採用了相同的構想。
- 本 skill 沒有使用上游的任何文字。原因：依本工作流的審查紀錄，該資料夾只有一個 `SKILL.md`，沒有授權檔，frontmatter 沒有授權欄位，儲存庫根目錄也沒有授權檔，授權條件未能確認；在沒有授權聲明的情況下，本 skill 不取用它的任何文字。該儲存庫的 `README.md` 只概括寫到其中許多 skill 以 Apache 2.0 開源，沒有指明這個資料夾；審查者另外確認，其餘 18 個 skill 資料夾各有 `LICENSE.txt`，只有這個資料夾沒有。
- 撰寫者與修訂者都沒有開啟該資料夾內的任何檔案，全部內容依 week833 的需求說明重新撰寫，只沿用上述構想。
- 本 skill 是 week833 的原創著作，以 MIT 授權發布（見 [LICENSE.txt](LICENSE.txt)），與 Anthropic 沒有隸屬或背書關係。

## 與上游的差異

本 skill 不是上游文字的改寫。下列括號內的比對結果，來自本工作流的審查階段：一位審查者以唯讀方式讀過上游 `skills/doc-coauthoring/SKILL.md`（同一個 commit），比對對象是本 skill 修訂前的版本。

- 沒有沿用上游的任何文字，所有檔案都是重新撰寫。（審查者沒有發現照抄或近似改寫的句子。）
- 依需求說明，這個構想是上游 `doc-coauthoring`（文件共同撰寫）skill 的其中一個階段；本 skill 只做讀者測試，不含撰寫文件的流程，對象限定為交接文件、ADR 與寫給下一個工作階段的 README。
- 下列內容是依 week833 的規則自行設計的：
  - 把文件交給讀者之前先檢查憑證，發現就停止，只回報位置與類型。（上游沒有這一步。）
  - 參考答案必須在啟動讀者之前依查證過的來源寫成，查不到就寫「未能確認」。（上游沒有參考答案。）
  - 整次測試只呼叫讀者一次。（上游是每一題各呼叫一次子代理，之後再呼叫一次檢查含糊與矛盾。）
  - 無法啟動子代理時，改由使用者另開工作階段，或在報告標示「未做獨立讀者測試」；主代理不得自行作答充當讀者。（上游也有由使用者另開新對話、貼上文件與題目的做法，構想相同，文字沒有沿用；「未做獨立讀者測試」的標示與禁止主代理代答，上游沒有。）
  - 比對時先核對引文是否確實出現在文件中，再依判定表取第一個符合的列；缺口分為缺漏、含糊、矛盾、過期四類。（上游也請讀者指出含糊與矛盾之處，構想相同；引文、「文件沒寫」與過期的檢查，上游沒有。）
  - 只提建議，預設不修改文件；建議文字只含查證過的事實。（上游在測試後直接回頭修改文件，並以讀者都答對作為文件完成的條件。）
  - 內容以繁體中文撰寫；專案的 `AGENTS.md` 與使用者的直接指示優先於本 skill。

## 已驗證

以下都在本工作流的 Linux 環境執行，記錄的是實際做過的檢查，不是給使用者照做的指令。所列的檢查腳本都是本工作流的工具，不隨 skill 發布；本 skill 本身沒有腳本、測試或範例可執行。

- 結構檢查：以系統的 CPython 3.11.18、3.12.3 與 3.13.18 分別用隔離模式（`-I`）執行本工作流的 `validate_skill.py`，另把語系設為 C、並以 `-X utf8=0` 關閉 Python 的 UTF-8 模式再跑一次，結果都是 `PASS`，沒有錯誤與警告。這個腳本檢查 frontmatter、`SKILL.md` 大小、`agents/openai.yaml`、相對連結、編碼，以及快取、位元組碼與符號連結這類不該發布的檔案；它不會發現多出來的 Markdown 檔，所以檔案清單另由下一項檢查。
- 文字檢查：在修訂者自建的 Python 3.12.3 虛擬環境（PyYAML 6.0.3、markdown-it-py 4.3.0）執行修訂用的檢查腳本，結果 `OK`。檢查內容：
  - 檔案恰為 `SKILL.md`、`NOTICE.md`、`LICENSE.txt`、`agents/openai.yaml` 與 `references/question-bank.md` 五個；全部為 UTF-8（無 BOM）、LF 換行、結尾恰有一個換行，沒有行尾空白、Tab 與不可見字元，所有字元都能以 cp950 表示（只是編碼對照，不代表在 Windows 上實測過）。
  - PyYAML 能解析 `SKILL.md` 的 frontmatter 與 `agents/openai.yaml`，鍵、值、長度與格式符合規定；`SKILL.md` 為 5,991 位元組。
  - 以原始文字逐列計算每個表格以 `|` 分隔的欄數，各表格每一列一致；markdown-it-py 解析時會把每一列整理成與表頭相同的欄數（多的捨去、少的補空），所以欄數不能只靠解析結果判斷。沒有 HTML，相對連結的目標都存在。
  - 讀者提示詞的規則編號 1 到 8 連續，規則 1 引用的分隔線與實際分隔線完全相同，待替換的〔〕只有讀者設定、文件全文與題目三種。
  - 下列用詞在 `SKILL.md` 與 `references/question-bank.md` 都出現：答對、答錯、文件沒寫、含糊、未能確認、未測、缺漏、矛盾、過期、未做獨立讀者測試、使用者另開工作階段、子代理、主代理、讀者提示詞、判定細則，以及七個題目類別。
  - 中文字旁沒有半形的逗號、分號、冒號、問號、驚嘆號與括號；沒有列在檢查清單上的中國大陸用語。
- 檢查腳本的有效性：把四份故意改壞的複本交給上一項的檢查腳本，分別是表格某列多一欄、某列少一欄、多一個最上層的 `README.md`、`references/` 下多一個沒有被引用的檔案，四份都被判為不合格；同樣四份交給 `validate_skill.py` 都是 `PASS`。
- 判定表：修訂用的列舉腳本先確認腳本內的 16 列與 `references/question-bank.md` 判定表的前四欄文字、順序完全相同，再列舉 39 種情境（讀者回答的種類、引文是否有效、文件內容、參考答案狀態、差異原因、指向來源的狀態），套用文件寫明的兩個前置步驟後由上而下取第一個符合的列：沒有任何情境找不到對應的列，也沒有情境的結果與預期不同。
- 引文核對方法：以 week833/stock（`a74eb97`）的 `docs/HANDOFF.md` 試三段跨行或含 Markdown 標記的真實引文與一段虛構引文。逐字搜尋與只去空白的比對都找不到三段真實引文；依本 skill 寫的方法去掉空白、換行與標記後三段都找得到，虛構引文找不到；改用一小段不含標記與標點的文字搜尋，三段都找得到正確的行（其中一段另有兩行也含有同一小段，要再對照前後文），虛構引文沒有結果。
- 提示詞試組：以撰寫時的組裝腳本，用 week833/stock（`a74eb97`）的 `docs/HANDOFF.md`、ADR-0007 與根目錄的 `README.md` 各組一次讀者提示詞。只在記憶體中組裝，沒有交給任何讀者。三份文件都不含與分隔線相同的文字，文件全文在兩條分隔線之間保持原樣，題目排在文件之後；`HANDOFF.md` 組出的提示詞為 38,978 位元組。審查階段另以一份故意含有分隔線的文件確認：分隔線不改時文件會被提前截斷，依本 skill 的規定改用其他分隔線並同步修改規則 1 後恢復正常。
- 編碼對照：把 `docs/HANDOFF.md`（UTF-8、無 BOM）的位元組改用 cp950 解碼，會得到大量亂碼，原本的引文也找不到；這是本 skill 要求以 UTF-8 讀取的原因。這只是在 Linux 上用編碼器模擬，不代表 Windows 上實際的讀檔行為。
- 路徑存取：在 Linux 上檢查 `D:\` 開頭的路徑，結果都是不存在；同一個檔案換成 week833/stock 複本根目錄下的位置（`docs/SOURCE_REGISTRY.md`）則存在。這是判定細則把「目前環境無法存取」與「來源不存在」分開處理的原因。
- 審查者的檢查腳本：兩位審查者各自的檢查腳本也在修訂後的版本重跑（上游比對那一段沒有執行），涵蓋字元類別、cp950 與 big5、半形標點、中英文間距與不該出現的字詞。命中的地方都逐一讀過：用詞命中的是台灣的一般用法（例如支持、通過、項目、目錄、腳本）或跨詞的字串誤判（例如「事實時」），標點命中的只有 YAML 字串的引號，其餘命中的都是禁止事項、出處說明、執行紀錄，或「沒有在 Windows 上執行過」這類照實的聲明。

- 上游比對（審查階段）：審查者逐句比對上游 `SKILL.md` 與本 skill 修訂前的版本，沒有發現照抄或近似改寫的句子；英文部分以 3 到 6 個詞的連續片段比對，只有一個 3 詞的通用片語相同。

- Codex 是否提供子代理，以及子代理或新的工作階段會不會自動載入專案規則檔、自行讀檔，都未能確認；skill 內文已照實標示。
- agent 在 Windows 上讀檔時實際採用的編碼未能確認，只做過編碼器的對照。
- 上游 `doc-coauthoring` 資料夾的內容、授權狀況與比對結果，都引用自本工作流的審查紀錄與審查者的複核；撰寫者與修訂者沒有開啟該資料夾，沒有自行複核。審查者比對的是修訂前的版本，修訂時新增的文字沒有再與上游比對。
